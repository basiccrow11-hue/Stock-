# Stock Replay

A trading simulator for practising when the market is closed. Replay a past trading day bar by bar without seeing what comes next, paper trade it with realistic orders, journal every trade, review your execution, backtest rule-based strategies, or trade a fictional market that never closes.

Everything runs in your browser. Nothing touches a real brokerage account.

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
```

Other scripts:

| Command | What it does |
| --- | --- |
| `npm test` | Unit tests (Vitest): orders, fills, positions, P/L, shorts, indicators, backtests, risk, replay and look-ahead prevention, streak rules, theme contrast, the Vercel proxy |
| `npm run typecheck` | TypeScript, strict mode |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Serve the production build (keeps the data proxy for Polygon/Alpaca) |

Requires Node 20.19+ or 22.12+ (the test runner needs 22.12+). Node 21 and 22.0 to 22.11 are not supported by the build tools.

## Read this first: what the data is

Every chart, trade and journal entry carries a badge saying where its prices came from.

| Badge | Meaning |
| --- | --- |
| **DEMO · SYNTHETIC** | Bundled offline bars for SPY, QQQ, IWM, AAPL, MSFT, NVDA, TSLA, AMZN, META, GOOGL and AMD from 2019 onward. They are **generated**, not recorded. They behave like real tape (opening volatility, lunch lull, trend and range days, gaps, earnings days, correlation with the index) but they are **not the real prices** of those tickers on those dates. Good for practising mechanics; useless for studying what actually happened. |
| **HISTORICAL** | Real recorded bars: a CSV you import, or Polygon / Alpaca with your own API key. |
| **SIMULATED · FICTIONAL** | The fictional market: six made-up companies, generated prices, generated news. |
| **LIVE** | Not available. There is no live feed and no real-money trading. |

To practise on real price action, import a CSV or add a vendor key (see below).

## Features

**Historical replay.** Pick a ticker, date, start and end time (ET), single or multi-day, chart timeframe (1m, 5m, 15m, 30m, 1h, 4h, 1D), starting balance and speed. Play, pause, step one bar (one minute on 1-minute data), step one chart candle, step back one bar, restart, change speed (up to 6.5 hours, one regular session, per second), jump to a time (the Jump to… menu at the end of the replay controls; Enter in its fields jumps). Play runs at the chosen speed on any base timeframe, so an hourly bar takes its hour and a daily bar its session. Only time outside the data's trading hours is skipped, by the calendar: nights, weekends, holidays, the afternoon of an early-close day, and the pre-market or after-hours when the data's recent sessions had no bars there (a replay whose start and end times include them still plays them). Inside those hours time passes at the chosen speed even when no bar comes, so a trading halt or a thin stock's quiet stretch lasts as long as it did, rather than the clock jumping to the next bar and telling you when trading resumes. Step, by contrast, always goes to the next bar, or to the end time when no bar is left before it. Watchlist symbols can replay on the same clock. **Blind mode** hides the calendar date everywhere (clock, chart axis, crosshair, journal, exports, in every open tab of the app) while the session runs. The chart's axis labels are placed on a calendar moved by some years, so their spacing does not mark real month or year starts, and the session's trades are listed first in the journal rather than among your other trades by date. The session ends when the replay reaches its end time (data that stops before it, such as a halt into the close, does not end it early), you start another session or you close the tab. **Starting another session** loads it first: if it cannot load (a vendor error, say), the running session carries on, paused, and the error is shown in the form, or as a message if you closed the form. Once it has loaded, the running session ends; if it holds open positions you are asked first, and they are closed at the last price, as a market order would close them (spread, slippage and commission as usual, all at once), and journaled with the exit reason "Session ended". A ticker the demo or imported data does not have is flagged before you start. **Random date** picks a day for you (with imported data, one the data has bars for; a date it has no bars for is flagged before the session starts). A blind replay's date is not kept as the next session's default.

**No look-ahead.** Future bars live in private fields of the replay engine and are only handed out once their bar has *completed* on the replay clock. Higher-timeframe candles are built from revealed 1-minute bars, so a forming 15m candle only shows what has happened so far; the months of history a 30m to daily chart shows before the start hold only bars that ended before the start. Indicators are causal (value at bar *i* uses bars 0..*i* only). Tests prove that two datasets with identical pasts and different futures produce identical charts, indicators, fills and backtest results up to the present.

**Paper trading.** Buy, sell, short, cover. Cash, buying power (cash, 2× Reg T or 4× intraday margin), positions with average entry, unrealized and realized P/L, total value, day P/L, win rate and trade count. The right column holds the account (starting balance, cash, buying power, session, unrealized and realized P/L, closed trades and win rate), your open positions, one line each (pick one to chart and trade it, or close it at market), and the order ticket; before a session it has buttons to start one. The top bar always shows account value and day P/L, then buying power, unrealized and realized P/L, cash and the replay clock, in that order, as far as they fit on one row. Every order, fill and event is logged. Buy and Short only open or add to a position, as at a broker that tells them apart from Sell and Cover: an entry order placed while flat that would fill after a position the other way has opened (two-sided entries around a range, say) is cancelled with a message rather than turned into an exit. When an exit and an entry trigger at the same price (a stop at the other side's entry, or a gap through a stop and a resting add), the exit fills first: it closes the trade, and an entry that fills after that opens a new one, judged on its own. When a trade closes, the rest of an entry that had already filled into it is cancelled, with a message, so one order never opens trade after trade (with strict mode on, so are its other entries that way, below). So is the rest of an entry still filling (a big order on a thin stock) when its own stop loss fills, or its take profit fills and the rest could fill at or past it (a market order, a stop that has fired, or a limit at or beyond the target), so it never buys or shorts past its own exit; a limit short of the target stays working and gets its own stop loss and take profit when it fills. Close position also cancels the rest of an entry still filling into the position (a market order, a stop that has fired, which is one now, or one already partly filled), so it cannot grow back after the close; entries that have not started stay working, unless strict mode is on, which cancels them too, at once, even when the close waits for the open. The ticket says how much of an order filled when it fills in pieces.

**Orders.** Market, limit, stop and stop-limit; DAY or GTC; optional extended hours for limits. Stop loss and take profit attach as a one-cancels-other bracket. Once a position is open you can also protect it with separate exit orders: a Sell (or Cover) stop and a Sell limit target can both work for the same shares, alongside a bracket or instead of one, and you can sell part of a position while they work. Each exit can be for at most the shares held; whichever fills first takes its shares, and the others are cut to what is still held (the ticket says so when they overlap), so exits never sell more than you hold. The first stop and the first profit target placed this way on a trade that has none become the trade's stop loss and take profit, for the journal, the review and the challenges. The ticket shows estimated entry, position value, stop distance, dollar and % risk, potential reward and R:R before you submit, and can size a position from a risk % (commissions included). Beside the last price it shows a modelled bid and ask: the last price less and plus half the spread set in Data & Settings (wider outside regular hours), on the tick. It is not a real quote; a market order pays slippage and market impact on top. The submit button, with the warnings about the order and its result, stays in view at the bottom of the column while the rest of the ticket scrolls, except on a phone, where the trade screen is one scrolling column (see Chart, below) and the button stays at the end of the ticket. Size by risk sizes the whole trade as the trade review counts it: a new trade is this order to its stop, and an add gets what is left of the asked % once the shares you hold or have working that way are counted from the trade's first stop. The size is then cut to what the order would be accepted at (buying power, and with strict mode on its other limits; a market or stop order keeps a little buying power back for the price to move before it fills), and a note says what cut it. With shares already held or working that way, the ticket also shows the whole trade's risk with the order. Prices picked from the chart and targets set with the 1R/2R/3R buttons go to the stock's tick: a cent, or a hundredth of a cent below $1. The estimate is priced at the moment the order is placed. For a market or stop order it includes what its fill will be charged (half the regular-hours spread, since these orders only trade in regular hours, slippage and the market impact of that many shares against the last bar's volume, or a whole bar's if the last bar has no room left for them), so a larger size shows a worse entry; a market order that fills at the next bar's open, or a gap past the stop, can still cost more than planned. Working orders can be modified (click the price) or cancelled. A bracket whose stop or target sits on the wrong side of the price the entry would fill at is refused, and the ticket shows the same error before you submit. That price is a stop-limit's stop (never past its limit), since it fills near where its stop fires, and for a limit, stop or stop-limit already through the market it is near the last price rather than the order's own level (filled at once, at the next bar's open in conservative mode, or when the stock next trades if the order cannot trade yet, a plain stop placed in the pre-market say). The same goes for a working order whose price you change. Changing a working entry order's price runs the same checks as placing it, buying power and strict mode included.

**Fill model** (all configurable in Data & Settings):
- Market orders fill at the last price plus half the spread and slippage, or at the next bar open (conservative mode, which uses the next bar that starts after the order, even when that bar opens the next session). An order for a symbol that has not traded yet in the current session (at the start of a replay, with data that has no pre-market bars, a watchlist symbol whose first bar comes later than the others', after the close on a symbol with no after-hours bars, or in the simulated market before its first tick) waits for that symbol's next bar and never fills at an earlier session's close: placed before that bar starts, it fills at its open; placed while it is still forming (a daily bar is only shown at its close), on its prices after that moment. On daily bars, a market order placed while the replay is paused at a close (after a step) fills at that close.
- Inside a bar the engine walks an assumed path (open → nearer extreme → other extreme → close, or worst case for your position). Stops and limits trigger at their price level when the path crosses them; gaps fill at the open. A limit fills at its price when the path reaches it (with "trades through by one tick", once price has traded a tick past it: a cent, or a hundredth of a cent below $1), or at the better market price when it gapped through. A stop-limit whose stop has fired is a limit from then on: one the market already meets fills at once. An order trades only on prices after it was placed or last changed: placed partway through a bar (on 5-minute, hourly or daily data, or a daily symbol beside 1-minute ones), it can fill only on the part of that bar's path after that moment, never at an earlier high or low.
- Spread in bps or cents, wider outside regular hours; slippage in bps plus market impact by share of bar volume (charged on up to one bar's whole volume, so with no volume cap a larger order fills at once and pays the impact of one full bar, 5% at the default 5 bps per 1%; a sell never fills below the minimum tick; the simulated market's bars are one-second ticks, so there impact is measured against a minute of volume at the tick's pace, as on 1-minute data); per-share, per-order and minimum commissions (the per-order fee and minimum are charged once per order, however many pieces it fills in); a cap on the share of a bar's volume you can trade (larger orders fill partially and the rest keeps working; a stop fires when price crosses it even if that bar's cap is already used, and is a market order from then on, so what it could not fill fills from the next bars even if price comes back; every order filled against the same bar shares the cap, so splitting an order does not get around it). A bar with no volume (data without a volume column) has no cap.
- Market hours follow the NYSE calendar (holidays, early closes). Orders placed while closed wait for the session.

**Risk management.** Warnings such as "WARNING: This trade risks 4.7% of your account." never block a trade unless **strict mode** is on. Strict mode measures a trade's planned risk the way the trade review and the challenges do: every share from the trade's first stop loss, at its estimated fill (the one the ticket shows), against the equity the trade started with (today's, before it opens). It counts the shares you hold and your working entries on that side, at their worst over which of those entries fill (once you have sold part, the trade at its largest size, as the review does), and it also counts what the trade would lose if every stop fired at its first stop, so selling part and buying back higher cannot hide risk. Raising your stop does not make room for bigger adds, because the review counts from the first stop: leave room in the first entry if you plan to add. It refuses, in this order: any entry once the day's loss reaches its daily limit, open trades included, at any bar close that day once every symbol's bar closing then has been counted, or at a moment inside a bar where one of your orders fills or is reached, such as a stop that fires before an entry (with that stock at the price there and your other stocks where they stood when the bar began; a dip inside a bar that none of your orders reaches counts only as far as the bar's close) until the next session, even if those trades recover, with working entries cancelled instead of filled; an entry without a stop loss, or while shares you hold have no exit stop or a working entry has none; entries working together before you hold any that way, unless they share one stop loss (whichever fills first, that stop is the trade's first stop); an entry, its stop loss, or another working entry at or past the trade's first stop (to re-enter after a stop-out, place the order once the trade has closed); a trade over the risk limit; and a position over the position limit. An exit stop can be tightened, and moved back toward the first stop, but never placed or moved past it. When a trade closes, its other entries that way are cancelled with a message: they were measured as part of it, so place them again to check them as a new trade. Cancelling orders and closing positions are always allowed; changing a working entry's price is checked like placing it. Its limits: the estimate can be beaten by reality (a gap, a market order filling at the next bar's open, or an order bigger than one bar's volume cap filling over several bars as price moves, can fill past it, so the review can measure a little more than strict mode did), and before a trade opens its risk is a share of today's equity, so a loss before the entry fills can make the review's % slightly higher. A trade's first stop is its bracket's, or the first exit stop placed while it had none. Strict mode checks orders as they are placed and changed; it does not stop you cancelling a stop, which the review and the challenges then count as shares left without one.

**Chart.** Candles, volume, zoom and pan, ET time axis. A legend in the TradingView style shows the candle under the crosshair (the newest one otherwise) and each indicator's name and settings with its value on that candle in its line's colour; RSI, MACD and ATR panes carry their own title and values, and indicator labels on the price axis are named (EMA 9, BB upper, Signal). When the price pane is short, the legend flows onto fewer lines. Indicators: SMA, EMA, VWAP, Bollinger Bands, RSI, MACD, ATR and volume; add, remove, recolour and change periods. Charts of 30 minutes and up reach back 200 trading days: a replay loads a few weeks of 1-minute bars, and the first such chart loads the rest as 30-minute bars from your data source (demo, CSV, Polygon or Alpaca); the legend says while it loads, and says where the data begins when it has less. Long sessions stay quick: indicators are updated at the newest candles only, and the chart is handed the newest 2,000 candles, with older ones following as you scroll back. During play, while the newest candle is on screen, the chart lets go of the oldest again whenever it holds 2,000 more than it needs, so it stays under about 4,000 unless you zoom far out. Drawing tools: trend line, horizontal and vertical line, rectangle, support/resistance zone and Fibonacci retracement, saved per symbol and kept in place on every timeframe (moving one on a coarser timeframe shifts it by whole candles there). A point drawn to the right of the last candle stays on the candle that later fills that slot: nights, weekends and holidays take no room, as on the chart. Click a drawing to select it and drag it to move it (a Delete button appears in the chart's corner); click the bare chart to let go. Grab a rectangle or zone by its outline and a Fibonacci by its dashed diagonal (or any level once it is selected); their insides leave the crosshair, zoom and pan working. Your fills, open orders, stop and target lines are drawn on the chart. Click the ⌖ buttons on the ticket to pick a price from the chart (a click on a drawing picks too). A working order's price in the Orders tab is a button: click it or Tab to it and press Enter to change it (a refused change says why under the price and in the Activity log). A stop-limit shows its stop and its limit, each editable until the stop triggers; after that only the limit (if the stop triggers while you edit it, the edit is dropped and a message says so). On a touch screen, tap near a drawing's line to select it, then drag it or its handles; swipes and pinches over any other drawing pan, zoom or scroll as usual. On a phone, a screen up to 1180px wide and 640px tall (a phone in landscape, a small tablet) or any window up to 560px tall, the trade screen becomes one scrolling column: watchlist, chart, order ticket, then positions and orders; a vertical swipe on the chart scrolls the page. There the drawing tools are a row above the chart, and on a narrow phone the chart's toolbar wraps onto two or three rows. On other screens the drawing tools are a narrow column at the chart's left edge, and the toolbar keeps to one row in windows about 1000px wide or wider (two rows below that). The bottom panel (positions, orders, fills, closed trades, this session's journal, the log) collapses to its tabs with the arrow at its right and expands when you pick a tab. Outside the one scrolling column, drag its top edge to resize it, or Tab to that edge and use ↑ and ↓ (Shift for bigger steps), Page Up and Page Down, Home and End; in the column it keeps a fixed height. Its size and whether it is collapsed are remembered in this browser. On other screens under 750px tall (a 1366×768 laptop) it starts collapsed, so the chart keeps its room.

**Journal.** Each closed trade creates an entry automatically: symbol, direction, entry and exit, size, average prices, stop, target (a stop or target placed after entry is shown with how long after), P/L, return, R multiple, holding time, commission, a chart snapshot, a tag and notes (why I entered, my setup, what I did well, what I did wrong, what I would change). Notes save as you type, and an edit cut off by closing or reloading the tab is finished the next time the app opens (or by another open tab of the app, which also shows it). On the Trade screen, the bottom panel's Journal tab lists the running session's entries, with the chosen one's tag and notes editable there while the replay plays. Search, filter, export to CSV or JSON.

**Chart snapshots.** With snapshots on (Data & Settings), each journal entry gets a picture of its symbol's chart at the close. When the chart on screen shows that moment it is the picture, drawings and all. When it does not (the trade was on another symbol of a watchlist replay or the simulated market, or a fast step or a jump had already shown bars after the close), the symbol's chart is drawn off screen with the same theme, chart type, indicators and markers, from the bars shown up to the close and none after (on a 30-minute to daily chart, with the earlier history the chart had loaded, all from before the replay's start), from a little before the entry; it has none of your drawings, and the entry says so under the picture. Pictures drawn off screen are made one at a time after the trade closes, a few tens of milliseconds each. An entry without a picture says why: snapshots were off, or the picture could not be made or saved.

**Learning Mode.** When a trade closes, playback pauses and a review opens: exit reason (by the order that closed the most shares: a stop order is a stop loss whether it came from the ticket's bracket or was placed on its own, a limit that took profit is a target, a market order is a manual exit; a trade closed in parts lists each part), whether the stop filled where you planned or well past it (a gap; the half spread every fill pays does not count), whether a gap (or the volume cap, filling one order in parts) filled your entry past its own stop (R is then measured from where the order was expected to fill when you placed or last changed it: its own price, a stop-limit's stop, or about the last price for a market order or an order already through the market) or past its own target (planned R:R is then measured from that same price), was moved into profit or was widened (the stop that came with an add is named as your add's stop and judged by its own history: moved, widened, or placed wider than your first stop), whether a stop the volume cap filled in parts had its rest fill after price came back, whether you added past your stop (R is then measured from your first entry, and the risk rule counts as broken; when a stop that came with a later add sat past your average entry the review says R cannot be measured), a stop placed after entry (it counts as the trade's stop; the review says how long the trade went without one and how far it went against you meanwhile; R is measured from your average entry, and when the stop sat at or past it (a breakeven stop, for example, or one that shares added after it moved the average past) the review says R cannot be measured), the risk over the trade's life (the most at risk to your stops as any bar began, so a stop moved further away or shares added with a wider stop count, and for a stop placed late the open loss before it; shares left with no working stop, from a stop cancelled or expired or one covering fewer shares than held, are named, with how long after entry, and break the risk rule), MFE and MAE (best and worst open P/L, also in R), how much of the best open profit you kept, risk taken, planned R:R, stop distance in ATR, and a check against your own trading rules (the daily loss rule reads the day's P/L as the account's Day P/L does, positions carried from earlier days included; during a challenge, the rules as they were when it started). Rules of your own, written in Settings in your own words ("Only trade with the daily trend"), are listed there too: the app cannot check them, so you mark each one Followed or Broke, and the mark is kept with the trade in the journal. After a stop, the review adds what price did next once the replay has shown a fixed stretch after the exit (20 minutes on a 1m chart, up to 4 weeks on daily; data coarser than the chart, such as a daily file on a 1m chart, is measured in its own bars), so the verdict is the same at any replay speed; if the replay ends first it goes by what was shown. When several trades close in one step, their reviews open one after another. It explains what happened; it never suggests a trade.

**Analytics.** Net P/L, return, win rate, winning, losing and breakeven trades, profit factor, expectancy, average R, planned R:R, average win and loss, payoff ratio, largest win and loss, max drawdown, losing streak, holding time and commissions, plus an equity curve and an R-multiple distribution. Breakdowns by symbol, tag, direction, entry hour, weekday and exit reason. Filter by data source, replay vs simulated market and tag; rewound sessions are excluded by default. The view says which data sources its trades come from, with their labels; when it adds together trades on real, synthetic (demo) and fictional (simulated) prices, a note says so and a table shows each source on its own (trades, won, lost, win rate, average R, profit factor, expectancy, net P/L).

**Backtester.** IF/THEN rules over price, EMA, SMA, VWAP, RSI, MACD (line, signal, histogram), Bollinger Bands, ATR or a number, with crosses above/below and is above/below, combined with ALL or ANY; actions buy, sell, short, cover (an exit rule's market order stays working until it fills, so what the volume cap leaves on one bar fills on the next, overnight included). Stop loss %, take profit % (both placed on the tick), sizing by shares, % of equity or % risk (a % size is capped by buying power, less 0.5% for the fill's costs, and the signal list says so), commission, slippage and spread, optional flatten before the close (in the session's last bar, the final minute on 1-minute data; what cannot be closed there, because a thin stock's data has no bar at the close or the volume cap lets only part of the position trade, is closed from the next session's open, with a warning naming the days; a daily candle is a whole session, so it does not apply to daily data or to the 1D signal timeframe, which both hold positions overnight, and the option says so). Signals are evaluated on **closed** candles and filled at the **next bar's open**. Indicators are warmed up on history from before the test's start: as much as the rules' longest indicator needs on the signal timeframe (its period, and for EMA and MACD three times it, for RSI and ATR five times, so the value they were seeded with has faded), up to about three years, loaded 50 trading days (about ten weeks) at a time, newest first, and kept as candles. If part of it cannot be loaded (a free plan's rate limit, say), the test runs on the recent part that was and says so. When the data starts too late, the results say which indicators were short and when they first had values. Results name a preset only while its rules and settings are the preset's own: edited rules show as "Custom rules based on" the preset. Results: stats, equity vs buy and hold, trades on the chart, trade and signal lists. Runs in a Web Worker: a year of 1-minute bars takes about a second, plus the time to load them. Cancel stops it while the bars are still downloading too. The page keeps your strategy, settings, results and a run in progress while you look at other pages, until the app is reloaded.

**Simulated market.** Start Market launches six fictional stocks with different personalities (growth, large-cap tech, small cap, blue chip, volatile momentum, index ETF). The companies and their news are invented; a ticker that matches a real listing does so by chance. Hidden bull, bear and sideways phases, trends, consolidation, overnight gaps, intraday volatility patterns and news events (earnings, analyst calls, lawsuits, economic data) that move prices. Every headline is labelled SIMULATED and shows on its stock's chart, in the News tab and as a short notice, whichever stock it is on (one notice every four seconds at most, naming how many more came with it). The watchlist names each stock's kind. Each stock is calibrated to its profile: over many sessions it realises its stated volatility (16% a year for the blue chip up to 95% for the volatile stock) within about a quarter, news, gaps and trends included, and moves with the index by its beta. Volatility clusters: busy and quiet stretches last from minutes to about an hour, then fade back to the stock's usual level. News moves are sized to each stock's volatility, so the volatility setting scales them too; more news means larger moves, and with news off a stock moves a little less than its profile. Volatility, news frequency, trend strength, regime and seed are configurable. Prices tick every simulated second, so at 1x, which the form starts at (a speed you chose before is kept), the tape updates every second like a live one; faster speeds run more ticks per frame, up to 300x (5 simulated minutes a second). The session's equity curve keeps one point a minute, as on 1-minute data.

**Daily practice streak.** The flame in the top bar counts the days in a row you reached your daily practice goal (5 to 60 minutes, default 10). Practice time counts while the tab is in front and you are active on any screen except Data & Settings; a playing replay keeps counting for 10 minutes after your last click or key press, since watching tape is practice too. The ring around the flame fills as you go. Click it for today's progress, your best streak, the next milestone (3, 7, 14, 30, 50, 100 days...) and a calendar of the last four months. Every 7th day you meet your goal within a running streak earns a streak freeze (you can hold 2); freezes cover missed days automatically, but only when you have enough for the whole gap. Days follow your computer's calendar, weekends included, and changing the goal never rewrites completed days. A milestone reached while a replay is playing gets a short note at once and its celebration when you pause, after any trade review, or the next time you open the app, as long as that streak is still running. So it never covers the chart mid-trade, and it waits while you are typing in a field so no keystroke lands on it. Two open windows count the same minutes once. The streak rewards practice time, never profit or trade count, so there is no reason to force a trade to keep it alive. It is stored in your browser.

**Appearance.** Data & Settings → Appearance, or **Chart style** in the chart toolbar for quick changes while you trade. Themes: Midnight, Graphite and Light, plus an accent colour. Chart type: candles, hollow candles, OHLC bars, line or area. Candle colour presets (classic, green/red, colour-blind safe blue/orange, cyan/magenta, monochrome) or your own up/down body, border and wick colours; chart background, grid, axis text and crosshair; grid lines on or off, magnet crosshair, last price line, normal/log/percent price scale (percent labels measure from the first bar on screen and indicators keep their true position; grid lines sit on round prices, so their percent values are not round numbers), volume opacity and axis font size. A live preview shows the result, and a note under the colour fields says when a colour is hard to see. Profit and loss text can follow your candle colours (colours that would be hard to tell from each other or from the grey text around them, such as monochrome or pastel candles, fall back to green and red; colour-blind-safe pairs such as Okabe-Ito or Tableau blue and orange are kept; errors always stay red). The panels and the chart legend decide separately, since a custom chart background can make colours that work on the panels hard to read on the chart; a note under the setting says which fell back. For shades right at the edge of these rules, the choice already on screen stands, so dragging a colour picker does not flicker between them. Text, chart markers, axis labels, drawing labels and indicator lines are nudged automatically when a colour would be hard to read on its background (WCAG 4.5:1 for text, 3:1 for lines), as little as possible. The last-price line and its label mark the last bar on screen (the newest one unless you scroll back) and share one colour, so the line can come out slightly lighter or darker than your candles. Data source labels always stay on the chart.

**Challenges.** Grow $10k to $12k risking ≤1% per trade (a stop placed after entry counts, but the risk is counted over the trade's life: a stop moved further away, the open loss before a late stop, and shares left without a stop all count); trade a day without a 5% drawdown; average 2:1 planned R:R over 10 trades; achieve 2:1 reward/risk over 10 trades (what the trades made in R: average win at least twice the average loss; a trade with no R, such as one whose first stop was placed at breakeven after entry, fails it); 20 trades following your rules (the rules as they were when the challenge started; with rules of your own, a trade counts once you have marked them on its review, one marked broken fails the challenge, so you are asked first, and a trade whose journal entry you delete does not count); positive expectancy over 15 trades. A result is *official* only if you never rewound the session. Past attempts show where their prices came from (demo, historical or simulated).

## Using real data

### CSV import (works offline)

Data & Settings → Import historical data. Needs columns for time, open, high, low, close and ideally volume. Header names are matched loosely (`timestamp`, `datetime`, `date` + `time`, `o`/`h`/`l`/`c`/`v`, Nasdaq.com's `Close/Last`, ...). Timestamps may be Unix seconds or milliseconds, ISO 8601 with or without offset, or dates with the year last (01/16/2024, 16/01/2024, 16.01.2024): a first number over 12 anywhere in the file makes them day/month, a second one makes them month/day, and a file where every date could be either is read as month/day (day/month when dotted) with a note in the preview. Dates that do not exist (month 13, 31 April) are rejected, not rolled over. Prices written with a decimal comma (185,64, as files from many European locales are) are recognised, and so are abbreviated volumes (82.49M). A comma that could be either (1,234) is settled by the rest of the file (other prices, the volumes, a `;` delimiter, dotted dates); when nothing settles it, it is read as grouping thousands and the preview says so. Without volume, fills are not capped by bar volume and VWAP is not meaningful. Times without a zone are read as New York time by default (switchable to UTC), and there is an option for vendors that stamp bars with their close time (a day's short last bar, like a 4-hour file's 13:30-16:00 bar stamped 16:00, then starts where the bar before it ended, as does a half day's, whose after-hours end at 17:00, and a day missing a bar still reads at the file's size, and in a regular-hours file a day's first bar starts no earlier than 09:30, like an hourly file's 09:30-10:00 bar stamped 10:00, as in the vendor's open-stamped export; daily rows stay daily with the option on; a file whose stamps look like the other convention, some at the session's end and none at its start or the reverse, gets a note pointing to that option in the preview, or is refused with that pointer when its bar size only fits the other way). 1-minute bars give the most realistic fills; daily bars work for daily replays and backtests. The bar size (1, 5, 15 or 30 minutes, 1 or 4 hours, or daily) is read from the spacing between bars, ignoring nights, weekends, minutes with no trades and any gap that spans the 09:30 open or the close (where hourly bars on the clock hour meet a session that opens on the half hour), so a thinly traded stock's 1-minute file is still 1-minute; a file spaced at a size the replay does not support (2, 3 or 10 minutes, 2, 6, 8 or 12 hours, weekly or monthly rows) is refused rather than relabelled; a daily file with the odd second row on a day, 6 hours or more from the day's other row, stays daily, and the preview says how many rows were merged. The ticker is guessed from the file name, including TradingView's `NASDAQ_AAPL, 1D.csv` and class shares such as `BRK.B`; check it before saving. Each daily row is filed under the day it names, whatever time it is stamped with (midnight UTC, midnight New York, the open or the close), so a day's bar is never shown before that day has traded; rows dated on a weekend or a day the NYSE was closed are skipped and listed in the preview (the holiday calendar follows history: MLK Day from 1998, Juneteenth from 2022). Importing another file for a ticker that already has data adds its bars to that data (where both have a bar at the same time, the new file's is kept), or replaces it if you choose; a file with a different bar size replaces it after you confirm. On a chart at the file's own bar size (or finer) each bar is its own candle at its own time, as the vendor placed it (hourly bars on the clock hour, a 09:30-10:00 first bar, 4-hour bars from 04:00), and backtests at that size evaluate every bar; coarser candles are counted from the 09:30 open. A bar shorter than the file's size (that 09:30-10:00 bar, yfinance's 09:00-09:30 pre-market hour) is complete, in replays and backtests alike, when the next bar opens. A bar is shown once it is complete, so with an end time before a bar's end (hourly bars stamped 15:30 run to 16:30) that last bar is not shown. Imports are stored in your browser (IndexedDB).

### Polygon or Alpaca

The browser cannot call these APIs directly (CORS), so the dev and preview servers include a small proxy at `/api/polygon` and `/api/alpaca`, and a Vercel deployment gets the same proxy as a function (see below). A plain static host without either will not work for vendor data; the app says so when it detects one.

Keys, three options:
1. **Session only (default):** paste them in Data & Settings. They live in memory and are gone on reload.
2. **Encrypted in the browser:** save them with a passphrase (AES-GCM, key derived with PBKDF2). You unlock them each session.
3. **Server side (local dev):** put them in `.env.local` next to `package.json`. The browser never sees them; the proxy adds them. On Vercel see [Deploying to Vercel](#deploying-to-vercel) before doing this.

```bash
# .env.local  (git-ignored)
POLYGON_API_KEY=...
ALPACA_KEY_ID=...
ALPACA_SECRET=...
```

Keys are never hard-coded and never logged. `/api/server-keys` reports only whether a key is configured. `.env` and every other `.env.*` file are git-ignored too (only a `.env.example` would be tracked), so a key put in the wrong one is not committed.

## Deploying to Vercel

The repository deploys as is: `vercel.json` builds the Vite app into `dist/` and adds a small function, `api/proxy.ts`, that replaces the dev server's data proxy for Polygon and Alpaca.

- The function forwards only the two bar endpoints the app uses, so it is not an open proxy.
- On a public deployment it forwards only the keys a visitor enters in their own browser. Keys in the project's environment variables (`POLYGON_API_KEY`, `ALPACA_KEY_ID`, `ALPACA_SECRET`) are ignored unless you also set `ALLOW_SERVER_KEYS=true`, because otherwise anyone with the URL could spend your quota. Only set it on a deployment protected by Vercel Authentication or a password.
- Everything else (journal, streak, settings, imported CSVs) stays in each visitor's browser. There is no database and no account.

## Honest limits

- **Demo data is synthetic.** See above. Do not draw conclusions about real tickers from it.
- **Fills are modelled from bars, not an order book.** The engine knows each bar's open, high, low, close and volume, not the order in which prices traded inside it, so it assumes a path. Queue position for limit orders is not modelled ("touch" fills as soon as price reaches your limit; choose "trade through" for a stricter rule). Spreads are a configurable model, not historical quotes.
- **Price level can hint at the era in blind mode.** Blind mode hides dates, but a real ticker's price level (for example SPY near 590) still narrows down when it was.
- **Sessions do not survive a page reload.** The journal, analytics, imported data, settings and drawings persist; an in-progress replay or simulated market does not.
- **A failure stays in the part of the app it happened in.** If a page, a terminal panel, the top bar or a dialog hits an error while drawing, or a page's code cannot be downloaded (a dropped connection, or a new version deployed since the tab was opened, which only a reload fixes), a message takes its place with Try again (which downloads a page's code again) and Reload the app, and the rest of the app and the running session carry on. Playback pauses if the chart panel, which holds the replay controls, is what failed. The message says that reloading ends the session.
- **Rewinding rewrites history.** Stepping back past a closed trade undoes it and removes its journal entry (you are asked first), and the session is flagged as not blind. Jumping back to a time restores the account as it was at that moment, orders placed then included; Restart returns to the starting balance with no orders. Going back before the first new bar has appeared (Restart at the start, or after Play was paused within the first minute) is not a rewind, since nothing after the start has been seen.
- **Vendor data needs the proxy and a network.** Polygon and Alpaca were implemented against their documented APIs and are tested with mocked responses; plan limits (history depth, rate limits, IEX vs SIP volume) are the vendor's.
- **Single user, single browser.** Data is stored locally; there is no account or sync. Clearing site data resets the journal and the streak.
- **The streak measures time, not quality.** It cannot tell focused practice from leaving a replay playing; it only stops counting after 10 minutes without input. It is a nudge to show up, not a measure of skill.

## Architecture

```
src/core/            framework-free engine (fully unit tested)
  time.ts            NYSE calendar, sessions, ET conversion (DST-safe)
  data/              MarketDataProvider / HistoricalDataProvider / StreamingDataProvider interfaces,
                     demo generator, CSV parser + provider, Polygon + Alpaca providers,
                     SimulationDataProvider, bar aggregation
  replay/            ReplayEngine (one symbol, hides the future) and ReplaySession (multi-symbol clock,
                     broker, step-back checkpoints)
  broker/            SimBroker (orders, fills, positions, brackets, P/L) and execution config
  indicators/        causal SMA, EMA, RSI, MACD, Bollinger, ATR, VWAP, and streams of them that the
                     chart updates at the newest candles (identical to recomputing everything)
  risk/              pre-trade risk assessment, position sizing, strict mode
  backtest/          rule definitions and the backtester
  sim/               fictional market generator and news
  analytics/         performance statistics
  learning/          post-trade review
  challenges/        challenge definitions and evaluation
  streak/            daily practice streak rules (goal, freezes, milestones, calendar)
src/ui/              React UI
  state/             zustand stores; tradingStore runs the play loop and bridges engine → UI;
                     streakStore tracks active practice time
  theme/             themes, colour maths (WCAG contrast) and the resolved palette for CSS and charts
  chart/             lightweight-charts wrapper, drawing layer, line charts, journal snapshots drawn
                     off screen from the same chart parts
  components/        terminal panels, order ticket, dialogs
  pages/             backtest, journal, analytics, challenges, settings
vite.config.ts       dev/preview proxy for vendor APIs, server-side key injection
api/proxy.ts         the same proxy as a Vercel function (deployed builds)
vercel.json          build settings, proxy rewrites, security headers
```

The engine has no browser dependencies, so new data sources plug in by implementing `HistoricalDataProvider` (see `src/core/data/provider.ts`) and registering it in `src/ui/state/dataRegistry.ts`.

A streaming session (today, the simulated market) reaches its prices only through `StreamingDataProvider`: its symbols, its clock, updates by subscription (each with the tick that orders fill against), the bars so far and its news. The simulated market is a `DrivenStreamingProvider`, a stream whose clock the app moves at the chosen speed; a live feed would implement the same interface and push updates on its own clock instead. No live feed ships: the build environment could not reach any market-data provider to build and test one against.
